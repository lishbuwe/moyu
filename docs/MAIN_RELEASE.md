# 主网页 0.6.16.12

## 0.6.16.12 转发限流诊断

- 上游接口返回 429 且转发任务已创建时，不再自动创建第二笔模型请求；保留状态码和返回原文供排查。直连仍沿用原来的无正文重试规则，明确拒绝的兼容参数仍可自动降级。
- 429 错误提示明确来源是模型接口，并提醒检查提供方频率、额度和逐章整理是否共用正文连接。转发服务器本身只转送请求和上游状态码；本次无需更换服务器程序。旧存档与连接配置不变。

## 0.6.16.11 结构化记忆、正文分层与番外时间点（阶段 2～4）

- 旧档案首次打开故事时原位迁移，保留所有旧栏目、章段摘要、角色状态和迁移前原文副本；没有确切章节或知情者的旧条目保留范围并标为未知。每条新记忆记录来源、人物、地点、物品、类型、重要度、知情者、别名、分支及失效版本。手动编辑继续通过旧栏目写回；一次只整理一章，已整理的章节版本不会重复自动整理，故事可选整理连接。旧故事明确设置过的整理频率保持原值。
- 正文默认发送关键核心、当前状态、最近两章原文和本轮检索结果；最近原文可在记忆页设为 2～4 章，也能切回旧整包。人物、地点、物品、别名、重要度和时间参与检索；超预算时先裁检索内容，固定资料或近期原文仍过大则在发送前提示。完整旧档案保留在本机，不要求重玩。
- 番外从所选分支截至时间点的全部合格记忆检索；旧摘要横跨时间点时先排除。角色卡的当前状态采用当时最近档案，未来新增角色不进入请求；旧番外重写和续写会重新生成时间点素材。公开或角色视角只取确认其知情的记忆，未标知情范围的旧原文不发送；全知模式仍带时间点前的最近和手选章节。番外也检查连接输入预算。

注意：旧档案只有章段范围，不能自动还原其中每一条事实的确切章节和知情者；严格视角下可能需要后续章节重新整理才能召回。后来手改的世界设定或角色卡基础人设没有历史版本，早期番外仍应人工检查这些资料。规则、世界设定、角色卡和保底近期原文合计过大时，无法保证单轮一定在 7k～15k token。缓存命中与模型实际 token 仍以接口回报为准。阶段 5 的时间点快照和番外独立记忆分支未做。

## 0.6.16.10 提示缓存（记忆升级阶段 1）

正文系统提示按固定规则与设定、常驻角色卡、最近分支的前情档案、动态模块及相关角色、近期对话排列。Claude 原生连接以 `cache_control` 标记稳定前缀；接口不支持时自动撤掉标记重试。Vertex 连接可在连接编辑页主动开启显式缓存：支持的 Gemini 模型复用 10 分钟的完整系统提示，按项目、地区、模型和提示正文区分；不支持显式缓存的型号及过短提示跳过，创建失败保留原有发送方式。创建需要 Google 的写入及存储费用，墨游记录接口返回的创建 token 数，存储费仍以 Google Cloud 后台为准。用量日志区分总输入、缓存命中、缓存写入、普通输入。没有修改存档结构；缓存信息只在页面内存，刷新后重新建立。缓存不会降低模型实际读取的总输入，降低长期输入长度要靠后续记忆分层。

## 0.6.16.9 输入预算保护

正文连接新增每轮输入预算，旧连接默认 30000 字，可在连接编辑页调整。较早剧情仍按原有逻辑裁去；若规则、角色卡、整份档案或近期剧情仍超过预算，会在创建模型请求前提示各部分占用，不发送这次请求。后台任务接回只订阅原任务，不受新请求预算检查阻断。此预算按字符粗估，不能代替模型实际 token 上限，也尚未压缩整份前情档案。数据库结构和已有存档不变；直连与服务器转发共用同一发送前检查。
