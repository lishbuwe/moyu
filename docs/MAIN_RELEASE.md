# 主网页 0.6.16.21

## 0.6.16.21 游玩工具与整理频率

默认每 15 章整理一次前情。游玩页可直接出戏、设置导演指令和查看记忆。出戏回复可以转入讨论，或编辑后用于下一章。转发任务已满时单独提示。

## 0.6.16.20 点选 Vertex 模型

连接设置可刷新 Google 的 Gemini 模型目录。内置候选含 Neon 和 Hydrogen，目录暂不可用时也可直接点选。

## 0.6.16.19 游玩输入与番外视角

选项全文填入输入框，可修改后发送。双引号内为台词，其他文字为动作或心理。修复快速连点的重复行动。选项数量遵循单局规则，默认三个。判定角色和关键词时跳过弹幕与候选行动。限知番外使用公开资料和视角可知记忆，全知番外保留按时间点取材。

## 0.6.16.18 自动找回旧正文

- 按场景接续时，从玩家输入和当前场景自动提取词组，在本机检索当前分支的旧正文。人物名和别名辅助排序，无需维护关键词或额外调用模型。
- 本轮命中的旧原文通常会在同一场景继续保留三轮，受上下文预算和相关性限制。查看器显示章节、线索和保留轮数。现有存档可直接使用。

## 0.6.16.17 导入故事的正文横移

- 正文容器限制横向溢出，长文字继续自动换行。游玩页重新渲染时归正横向位置，编辑和选段重写只在正文容器内进行纵向定位。
- 现有存档可以直接打开，无需重新导入。

## 0.6.16.16 正文按场景接续

- 优先带当前场景的连续对话，整理前情时登记还在发展的互动和原文位置。相关角色重逢时可接回较早的关键原句，已有对白和关系变化优先于开局的状态描述。
- 章节菜单可保留最多三段原文。后续请求只使用当前分支中仍能核对的引用，查看器列出实际带入的章节、片段和未能带入的未整理章节。
- 沿用现有存档、整理频率和模型连接。旧档案中的早期互动不会凭摘要自动补写，玩家可以手动保留原文。尚未整理的场景先用原文中的时间、场景提示判断，识别可能有偏差。可在记忆页切回旧整包模式。

## 0.6.16.15 正文横移、断点续写与角色卡导入导出

- 正文阅读区只纵向滚动，长标题、链接、弹幕和选项在屏幕宽度内换行。
- 最新章可以续写。流式接口没发结束标记时保留已收到的内容并提示续写。若该章已整理进记忆、已有后续分支，或完成章已有弹幕或选项，则在新版本中续写。
- 角色页可导入单张墨游 JSON 角色卡，预览后保存同名角色或添加新角色。角色编辑页可导出或导入到指定角色，主角可单独导入导出初始资料。

## 0.6.16.14 iPhone 阅读布局与双击缩放

- 应用阅读区、弹层统一关闭双击页面缩放，同时保留正常滚动和双指缩放；放大期间不再把 visualViewport 缩小误判为键盘弹出，避免正文、底栏随视口跳动。
- 转发地址、服务账号 JSON 和一处修改框统一使用至少 16px 的输入字号，避免 iOS 聚焦输入时自动放大。合并番外弹幕重复覆盖的样式，呈现效果不变。
- 更新离线资源缓存版本，不修改故事、连接和存档结构。实际 iPhone Safari 与主屏幕模式仍需在设备上检验。

## 0.6.16.13 转发任务容量与整理频率

- 转发器的 20 个名额改为只计算运行中的任务；已完成任务仍供接回，极高用量时按 100 个结果或 64 MB 上限逐出最早的已完成任务。服务器程序需要在当前任务取回后更新并重启，单独更新网页不能解决旧转发器的“任务已满”。
- 升级前创建且没有单独设置过整理频率的旧故事恢复每 15 章自动整理一次，积压章节最多 10 章一批；新建故事仍为每章一次，已手动选过的频率不改。记忆页可自行调整频率或关闭自动整理。旧档案和结构化记忆保持兼容。

## 0.6.16.12 转发限流诊断

- 上游接口返回 429 且转发任务已创建时，不再自动创建第二笔模型请求；保留状态码和返回原文供排查。直连仍沿用原来的无正文重试规则，明确拒绝的兼容参数仍可自动降级。
- 429 错误提示明确来源是模型接口，并提醒检查提供方频率、额度和逐章整理是否共用正文连接。转发服务器本身只转送请求和上游状态码；本次无需更换服务器程序。旧存档与连接配置不变。

## 0.6.16.11 结构化记忆、正文分层与番外时间点（阶段 2～4）

- 旧档案首次打开故事时原位迁移，保留所有旧栏目、章段摘要、角色状态和迁移前原文副本；没有确切章节或知情者的旧条目保留范围并标为未知。每条新记忆记录来源、人物、地点、物品、类型、重要度、知情者、别名、分支及失效版本。手动编辑继续通过旧栏目写回；逐章模式一次整理一章，已整理的章节版本不会重复自动整理，故事可选整理连接。旧故事明确设置过的整理频率保持原值。
- 正文默认发送关键核心、当前状态、最近两章原文和本轮检索结果；最近原文可在记忆页设为 2～4 章，也能切回旧整包。人物、地点、物品、别名、重要度和时间参与检索；超预算时先裁检索内容，固定资料或近期原文仍过大则在发送前提示。完整旧档案保留在本机，不要求重玩。
- 番外从所选分支截至时间点的全部合格记忆检索；旧摘要横跨时间点时先排除。角色卡的当前状态采用当时最近档案，未来新增角色不进入请求；旧番外重写和续写会重新生成时间点素材。公开或角色视角只取确认其知情的记忆，未标知情范围的旧原文不发送；全知模式仍带时间点前的最近和手选章节。番外也检查连接输入预算。

注意：旧档案只有章段范围，不能自动还原其中每一条事实的确切章节和知情者；严格视角下可能需要后续章节重新整理才能召回。后来手改的世界设定或角色卡基础人设没有历史版本，早期番外仍应人工检查这些资料。规则、世界设定、角色卡和保底近期原文合计过大时，无法保证单轮一定在 7k～15k token。缓存命中与模型实际 token 仍以接口回报为准。阶段 5 的时间点快照和番外独立记忆分支未做。

## 0.6.16.10 提示缓存（记忆升级阶段 1）

正文系统提示按固定规则与设定、常驻角色卡、最近分支的前情档案、动态模块及相关角色、近期对话排列。Claude 原生连接以 `cache_control` 标记稳定前缀；接口不支持时自动撤掉标记重试。Vertex 连接可在连接编辑页主动开启显式缓存：支持的 Gemini 模型复用 10 分钟的完整系统提示，按项目、地区、模型和提示正文区分；不支持显式缓存的型号及过短提示跳过，创建失败保留原有发送方式。创建需要 Google 的写入及存储费用，墨游记录接口返回的创建 token 数，存储费仍以 Google Cloud 后台为准。用量日志区分总输入、缓存命中、缓存写入、普通输入。没有修改存档结构；缓存信息只在页面内存，刷新后重新建立。缓存不会降低模型实际读取的总输入，降低长期输入长度要靠后续记忆分层。

## 0.6.16.9 输入预算保护

正文连接新增每轮输入预算，旧连接默认 30000 字，可在连接编辑页调整。较早剧情仍按原有逻辑裁去；若规则、角色卡、整份档案或近期剧情仍超过预算，会在创建模型请求前提示各部分占用，不发送这次请求。后台任务接回只订阅原任务，不受新请求预算检查阻断。此预算按字符粗估，不能代替模型实际 token 上限，也尚未压缩整份前情档案。数据库结构和已有存档不变；直连与服务器转发共用同一发送前检查。
